### Fixed
- **Addresses are read the way the browser reads them.** A link or `fetch_url` address with a backslash or user info, such as `https://evil.com\@github.com/?d=…`, no longer passes as the site you named: Locus read the host after the `@` while the request went to the one before the backslash. Such an address now counts as one the agent chose and asks, and `[::ffff:7f00:1]` is read as 127.0.0.1. See [taint](docs/design/taint.md#the-rule).
- **Naming a hosting domain no longer trusts everyone on it.** Typing `github.io`, `vercel.app` or `co.uk` used to trust every subdomain, so a hostile page could send your data to `attacker.github.io` without a card. Shared hosting names (a compact copy of the Public Suffix List) are never named by typing and never cover subdomains; `docs.github.com` is still covered by `github.com`.
- **Look-alike brackets can't close the outside-content block.** Fullwidth `＜/untrusted_web_content＞` and small-form `﹤…﹥` (and fullwidth letters) are now defused like the ASCII tag, as are the same forms of `<locus_mode>` and `<locus_result>`.
- **`fetch_url` is stricter about where it goes.** Headers you or the agent set now go only to the same scheme, host and port after a redirect. A provider or connector at `http://192.168.1.5:11434` opens that port only, not the host's other ports. 192.0.0.0/24, 198.18.0.0/15, 240.0.0.0/4, NAT64, IPv4-compatible and 6to4 addresses are refused when the IPv4 address inside is private or reserved. See [taint](docs/design/taint.md#fetch_url).
