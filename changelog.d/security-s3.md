### Fixed
- **A connector's key no longer follows a redirect to another address.** `connector_call` let the app's HTTP client follow redirects, and that client forwards a custom key header (`X-Api-Key`, `PRIVATE-TOKEN`) to whatever host a service redirects to; only `Authorization` was dropped. A service with an open redirect, or a path the model was steered to, could collect your key (reproduced with two local servers). Locus now follows a connector's redirects itself, one checked hop at a time: each must stay on the connector's host, never go from https to http, and land on an address the key was saved for; the key is added to each request afresh, and a refused redirect says so instead of being followed. (#365)
- **A connector's huge reply no longer crashes the run.** `connector_call` read the whole reply into memory before cutting it to 30,000 characters, so a service sending hundreds of MB ended the task with an out-of-memory error. It now reads at most 2 MB and says "stopped reading at 2 MB" when the reply was longer. (#358)
- **A connector's script no longer sees a key the service echoes back.** The `response()` hook got the raw reply, and only the script's output was scrubbed of the key, so a script that re-encoded an echoed key (as hex, say) got it past the scrub. The reply is now scrubbed before the script runs. (#375)
