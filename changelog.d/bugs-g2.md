### Fixed
- **A failure around a tool call no longer leaves the chat with unanswered calls.** When something other than the tool itself failed while a step's calls ran (saving a long result to a file on a full disk, writing the activity entry, a check before the call), the run failed and the step's calls had no results until the next start, which then said Locus had been closed. Every call now gets its result before the error ends the run: the call being handled says Locus hit an internal error (and which) and that it may have run, calls beside it that finished keep their results, and the rest say they weren't run. Requests of existing chats don't change. *Not yet tried on the phone.* (#300)
- **After Locus was closed mid-step, the agent is told which call may already have happened.** Every call left without a result read "Not run: Locus was closed before this ran", including the one that was running, which may have sent the email or pushed the commit, so the agent often did it again. At the next start Locus now checks Activity: a call that finished says it did run, the one that was running says it may have completed and to check before running it again, and only the calls after it say they weren't run. No database change. *Not yet tried on the phone.* (#301)
- **Stopping during reads that run together keeps the ones that finished.** When you tapped Stop while Locus waited on the first of several reads running at once, the later ones that had already finished were recorded as "Cancelled by the user", with no Activity entry. They now keep their real results and Activity entries. *Not yet tried on the phone.* (#302)
- **A long test or linter run counts toward the context before the next request.** The check for summarising a long chat counted only a step's tool results, not the output of the project's after-edit rules that follows them, nor images, so a failing test run could push the next request over the model's window and into the slower overflow recovery. It now counts everything added since the last reply. *Not yet tried on the phone.* (#303)
- **The task budget asks once, and counts every request.** A step that went several budget sizes over (helpers count toward the same budget) asked Continue once per size, several times in a row with no work in between; one Continue now passes what's already spent. A summary started in the background and cancelled when the task ended was never counted; its prompt is now counted from an estimate, in the budget, the receipt and Insights. And chats on OpenAI-compatible providers other than OpenAI, OpenRouter and Groq (Gemini's endpoint, DeepSeek, xAI, Ollama and others) never asked for usage, so their receipts and Insights showed no tokens or cost; every provider is now asked, and one that refuses the option is asked again without it. These requests gain only the usage option; what the model reads is unchanged, so prompt caches stay valid. *Not yet tried on the phone or against live keys.* (#305)
