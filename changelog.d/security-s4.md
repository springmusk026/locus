### Fixed
- **Browser and artifact safety fixes from the November audit.**
  - **Confirmations in Spanish, Portuguese and Chinese.** Buttons and `confirm()` dialogs were only recognised by English words, so "Finalizar compra", "Eliminar cuenta", "Excluir", "支付" or "删除" ran without asking, and "Iniciar sesión", "Entrar" or "登录" on a sign-in page didn't count as signing in. The word lists now cover every language the app ships, with whole-word matching that works for accented words, and Chinese words match inside longer labels (#362).
  - **One-time-code and card fields in any case and language.** A field with `autocomplete="One-Time-Code"` wasn't treated as a one-time-code field, and card and code fields named `numero_tarjeta`, `cartao`, `validade`, `卡号`, `otp` or `codigo_verificacion` weren't recognised, so the agent could type into them or read them back in a snapshot. The page script now takes the same shared word list as the confirmations, case-insensitively; Spanish, Portuguese and Chinese search fields are recognised as searches too (#363).
  - **Downloads no longer send a site's cookies to another site.** A download link that redirected elsewhere got the original site's cookies, and the full page address as Referer. Redirects are now followed one by one, each with only its own cookies; the Referer is only the site's address, and a redirect from https to http is refused (#369).
  - **Artifacts can't reach WebRTC through a nested frame.** A new empty or `srcdoc` frame brought its own WebRTC, which the sandbox had only removed from the artifact's own window. Frame windows are now hardened as the artifact reaches them, and frames are removed as soon as they appear (they could never load anything here; a `srcdoc` frame used to show). DNS prefetching is asked off too. This is as far as script can close it; the rest is listed in [artifacts](docs/design/artifacts.md#known-limits). *Not yet tried on the phone* (#370).
