### Changed
- **CI runs every module's unit tests by one name, and the NDK version is written once.** `./gradlew unitTests`, registered in each module by the convention plugins (an Android module's debug unit tests, a plain Kotlin module's `test`), replaces the hand-written module list in CI, the release workflow, the verification-metadata script and the docs, so a new module's tests can't be left out without anyone noticing. It runs exactly the 26 test tasks the old list did; none had been missed yet. The NDK version lives in `gradle/libs.versions.toml` and `core:terminal` and every workflow read it from there instead of keeping five copies. Also: `actions/checkout` no longer leaves the token on disk in jobs that don't push, the native-libs workflow refreshes its package lists before installing and has a concurrency group, and the emulator snapshot cache is keyed by the system image's revision. Nothing changes in the app. (#330)
- **The app module has JVM tests, run on every pull request.** Robolectric tests cover what the other modules' tests can't reach: where shares, selected text, the assist gesture, the automation actions and the quick settings tile land (from the merged manifest), the static shortcuts' actions, the tile opening home's ask bar (after unlocking a locked phone), shares becoming a chat's draft (Direct Share only into a chat that is still a share target, a file that can't be imported named rather than dropped), every screen's route surviving the back stack's save and restore, the back-stack moves for shortcuts, widgets and notifications, and the app's Hilt graph. Those moves now live in a small `AppNavigation` object that MainActivity calls, with the same behaviour. (#332)
