### Fixed
- **Messages you queue while the agent works survive a power cut, and a damaged queue file is kept.** The queue is written to disk and flushed before it replaces the old file, instead of being replaced while still in the cache, so a phone that dies mid-write no longer leaves an empty file behind. A queue file that can't be read is kept as `<chat>.json.corrupt` instead of deleted, and it, like a queue that couldn't be saved (a full disk), is now recorded in Settings → About & privacy → Diagnostics rather than skipped without a word. *Not yet tried on the phone.* (#313)
- **A task "every morning at 7" stays at 7 when the clocks change, and a nearer trigger check isn't dropped.** A daily or weekly task that starts at a time of day now runs at that local time each day, so after the spring change a 7:00 briefing no longer arrives at 8:00 for good. Each run sets up the next one for the same local time. The tradeoff: changing such a task's conditions while its run is going now stops that run. Separately, asking for a later check of an event trigger (a calendar entry, a new save) no longer cancels a nearer one that is still waiting. After a trip to another time zone, the one run already waiting still comes at the old zone's time. *Not yet tried on the phone.* (#314)
- **Reminders follow you across time zones, and their buttons are translated.** A reminder set for a clock time ("9:00 tomorrow") stays at that time when the phone's time zone or clock changes, so the Lisbon 9:00 reminder no longer fires at 4:00 in New York. Snooze 10 min and Done on a reminder are now in your language, and the Allow/Deny, Stop/Continue and question buttons on the agent's notifications can no longer answer another request's notification when their internal numbers happen to match. A reminder due between a reboot and the first unlock still shows only at the unlock, marked late. *Not yet tried on the phone.* (#315)
- **Activity refreshes less while the agent works.** Browsing Activity (no search text) no longer reruns each time a chat is written during a run, and a single chat's view uses its index instead of reading the whole log. A text search is shown at most every half second. Searching text still reads the whole log: a full-text index for it needs a database change that this release doesn't make. (#316)
- **A backup no longer freezes chat writes while it copies the database.** The copy now runs on its own read-only connection instead of Room's writer, so a message being saved isn't held up until a large database has been copied. *Not yet tried on the phone.* (#317)
