### Fixed
- **A helper that hits an error now ends and frees its place.** A helper whose work failed with an ordinary error (its chat couldn't be saved, say) never finished: it held one of the three helper places for good, a new helper that can change files was refused, `agent_wait` waited out its timeout and the chat never heard back, and nothing was logged. It now ends as failed with a report saying what went wrong (and what it had done), the main agent and the chat hear about it as for any helper, and the error is recorded in Diagnostics. (#295)
- **Finished helpers no longer pile up in memory.** Every helper started since Locus opened kept its model connection, tools and transcript in memory for good. Locus now keeps the latest 16 finished helpers whose reports were collected and lets older ones go; a helper still working or with a report nobody has collected yet is always kept. A helper let go is continued with `agent_send` from its saved chat, as after a restart (a forked helper can't be, and the tool says so). (#296)
- **Helpers count tokens as the task budget does.** A helper's token budget, the per-turn helper allowance and the tokens on a helper's row counted every request's whole prompt at full weight, so a helper re-reading a long cached prefix each step stopped with "used its token budget" up to ten times too early. They now count as the task budget does: cache reads at a tenth, a summary the provider wrote included. The token figure on helper rows is lower for the same work. (#297)
- **A helper over its token budget finishes its step instead of being cut off.** It was stopped the moment the reply that crossed the budget arrived, so that reply's tool calls never ran and were recorded as "Cancelled by the user", which the helper read as you stopping it when it was continued. The calls now run, the helper stops before its next request, and its report says it used its token budget. (#298)
- **Waiting for your approval no longer eats a helper's time limit.** A helper waiting for you to allow a command kept its clock running, so answering after the limit stopped it as out of time before it did the work. The time a card waits for you no longer counts, as with the task budget's time limit. (#299)
