### Fixed
- **The on-device model's repaired tool calls can no longer include page text.** When LiteRT couldn't read a Gemma tool call, Locus rebuilt it from the raw text, and text the model had copied from a web page (`…<|"|>}call:run_command{…}`) could become a second, hidden call; the word `recall:` counted as a call too, and two identical calls were merged into one. Now a call must start the block or follow a call's closing `}`, and any other text in the block makes the repair fail (the turn ends with an error and the model tries again, as before repair existed). Each block LiteRT rejected repairs to one call; a block that reads as several calls is refused, because it can't be told from page text. Identical calls from separate blocks are kept. A call rebuilt this way always asks you first, even where the tool is set to Allow, and in a background run it is refused. See [taint](docs/design/taint.md#repaired-on-device-tool-calls). (#366)
- **More token formats are hidden everywhere, and the diagnostics log is scrubbed as it is written.** Telegram bot tokens, Groq `gsk_`, Hugging Face `hf_`, GitLab `glpat-`, Slack `xapp-` and webhook addresses, and Google `ya29.` were not recognised, and crash and error reports missed private key blocks, JWTs and AWS key ids that only the publish page caught. The viewer, Activity, Diagnostics, the publish page and chat export now share one list. The vault's values are also taken out of every Diagnostics entry when it is written, not only when it is shown or shared, as soon as Locus has started (a crash in the first moments carries only the patterns). See [diagnostics](docs/design/diagnostics.md#scrubbing). (#373)
- **Local MCP server secrets: checked, and a check added.** The audit worried that a command could read a server's secrets from `/proc/<pid>/environ`. Locus already hides the whole `/proc/<pid>` of every server that holds secrets, `environ` included, from every Linux launch after it; the design doc now says so, and `tools/verify-linux-isolation.sh` has a new check (6b) that no readable environment under `/proc` has a credential-looking name. A program started before the server still sees it; that limit is unchanged and written down. *The new check hasn't been run on a phone.* See [Linux isolation](docs/design/linux-isolation.md#local-mcp-server-secrets). (#376)
- **`supabase_query` can no longer be pointed at the Vault through a function.** The check looked for `vault.` and `pgsodium.` in the query's code but not in strings, so `table_to_xml('vault.decrypted_secrets'::regclass, …)`, `schema_to_xml('vault', …)`, `database_to_xml(…)` and `ts_stat('select … from vault.decrypted_secrets')` got through. Those functions are now refused, and so is the word `vault` or `pgsodium` anywhere in the query (strings, quoted names and comments included) and names written with `U&"…"` escapes. Revoking the Vault from `supabase_read_only_user` in the Supabase dashboard is still the fence that matters. (#380)
- **A slow connection can no longer stall browser sign-in.** The listener for ChatGPT and MCP sign-ins read one connection at a time, waiting up to 3 seconds for each byte, so another app sending a byte every few seconds could keep it busy for hours while the browser's real redirect waited, and cancelling didn't stop the wait. Each connection is now read on its own, gets 3 seconds in all and at most 16 are read at once, and cancelling returns within about a quarter of a second. See [network](docs/design/network.md#the-sign-in-listener). (#381)
