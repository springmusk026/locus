### Fixed
- **GPT-6.2 and later now cache the system prompt.** Locus sent each chat's system prompt in the Responses `instructions` field, which GPT-6.2 and later models (Astra, Sol and newer) put after the conversation, outside the prompt cache, so every request paid for the whole system prompt at the full input rate. New chats on these models, on OpenAI's API and on your ChatGPT plan, now send it as the first `developer` message instead, as OpenAI's prompt caching guide says, and it's read from the cache on later requests (at 0.05x the input rate on GPT-6.2 Sol and Astra). Chats already under way keep `instructions`: moving the prompt in front of their history would make the API drop the reasoning they carry. Earlier models and other providers send exactly what they did. If a provider refuses the developer message, the request is sent once more with `instructions` and that provider gets `instructions` until Locus restarts. Each reply keeps a hidden note of where the prompt went, in the message itself: no database change. See [cost](docs/design/cost.md#system-prompt-placement-on-gpt-62-and-later). *Not yet tried against live keys.*
