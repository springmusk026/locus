### Fixed
- **A connection that drops while a tool call streams is retried.** On mobile data, a long `write_file` whose arguments were cut off halfway failed the whole run; now the step is asked again, as for a drop before any tool call (tools only run after a complete reply, so nothing runs twice). Waits between retries vary by up to 20 % so phones don't all come back at the same moment, a provider's `retry-after: 0` (or Gemini's `retryDelay: "0s"`) still waits a second instead of spending every retry in milliseconds, and `retry-after` dates in the older RFC 850 and asctime forms are read. *Not yet tried on the phone.* (#304)
- **Replies cut off by the server are retried, not saved as finished.** When a local Ollama or vLLM server crashed or a proxy's timeout closed the stream, Chat Completions and Anthropic chats saved half an answer as the final reply and reported the task as done. A stream that ends before its last event (`[DONE]` or a finish reason, `message_stop`), an event cut off mid-line, or a line that isn't valid JSON is now a retryable error. *Not yet tried on the phone.* (#306)
- **Parallel tool calls from servers that leave out `index` stay separate.** Some OpenAI-compatible local servers send each call in its own chunk without an index; two `read_file` calls were merged into one with invalid arguments and both were lost. Each now runs, and a call's card carries the same id as the call itself. *Not yet tried on the phone.* (#307)
- **Mid-stream errors keep their details, and reasoning stays on for unrelated errors.** A rate limit sent in the middle of a Chat Completions stream (OpenRouter) now keeps the wait the provider asked for, its words in your language and its body for Diagnostics. A 400 that only mentions reasoning, such as one about a replayed reasoning item, is no longer sent a second time without the reasoning settings, which doubled the cost and could lose encrypted reasoning for later turns; only an error about the setting itself is. *Not yet tried on the phone.* (#308)
