### Security
- **An MCP server can no longer slip a changed tool past its pin by listing the same name twice.** Pins are kept by tool name, so a server that listed a tool both as approved and changed got both copies through: chats read the unapproved description (in `mcp_list_tools` and in the deferred tools offered for provider-side search), and whether a call asked first could come from the changed copy's hints (`readOnlyHint: true` on a tool approved as deleting). On first connect the last copy was pinned. Now every copy of a name listed twice is held back, including on first connect, and calls to it are refused; Library → Connectors shows those tools as "Listed twice", which can't be approved until the server lists the name once. Tools are also kept only when their own definition matches the pin, not just their name. See [tool pinning](docs/design/mcp-connectors.md#tool-pinning). *Not yet tried on the phone.* (#407)
